# Exorus — техническое задание

> Дипломный проект: стриминговый сервис музыки. Рабочий документ, здесь только уточнённые решения.

**Название проекта:** Exorus
**Репозиторий:** GitHub, `exorus`

---

## 1. Тема ✅

> **«Разработка кроссплатформенного стримингового сервиса музыки с рекомендательной системой на основе машинного обучения и совместным прослушиванием»**

---

## 2. Общие условия

| Параметр | Решение |
|---|---|
| Разработчик | Один человек |
| Срок | Не ограничен, не критичен |
| Платформы | Веб-версия (ПК и телефон) + десктопное приложение для ПК |
| Источник музыки | Внешние сервисы через API: связка Jamendo + Deezer (свои треки не загружаются) |
| Принцип выбора стека | Популярные технологии, близкие к стеку Spotify |

---

## 3. Ключевые функции

### 3.1. Стриминг музыки
- Каталог, поиск, плейлисты, лайки, история прослушиваний.
- Адаптивный стриминг (HLS, несколько битрейтов).

### 3.2. Рекомендательная система на основе ML
- Гибридная модель:
  - **контентная часть:** аудио-эмбеддинги треков, полученные предобученной моделью (решает проблему холодного старта);
  - **коллаборативная часть:** модель по истории прослушиваний (ALS / two-tower), на старте обучается на публичном датасете;
  - **гибрид:** объединение и ранжирование кандидатов.
- Оценка по метрикам Precision@K, Recall@K, NDCG@K.
- Базовая модель для сравнения: `/tracks/similar` от Jamendo.

### 3.3. Синхронное совместное прослушивание
- Комната на 2–3 устройства.
- **Управляет только хозяин комнаты:** play / pause / seek / смена трека / очередь. Остальные участники только слушают.
- Если хозяин отключился, права передаются следующему участнику.
- Механика:
  - сервер хранит состояние комнаты (трек, позиция, серверное время старта, статус);
  - синхронизация часов клиентов с сервером (по принципу NTP, ping-pong);
  - отложенный старт («играть в момент T + ~1 с»), чтобы все успели загрузить буфер;
  - коррекция дрейфа: при малом расхождении playbackRate ≈ 0,98–1,02, при большом перемотка;
  - на мобильных устройствах кнопка «Присоединиться» (ограничение автозапуска звука в браузерах).

### 3.4. Встроенный мессенджер
- Чат внутри комнаты прослушивания.
- Личные сообщения.
- Отправка трека карточкой в чат.
- Работает поверх того же WebSocket-соединения.

## 4. Источники музыки ✅ (связка Jamendo + Deezer)

| Сервис | Роль | Что даёт |
|---|---|---|
| **Jamendo** | Основной источник полных треков, хранятся на своём сервере | ~600 тыс. треков под Creative Commons, скачивание через API (mp3 / ogg / flac), теги жанра, настроения, инструментов, `/tracks/similar` |
| **Deezer** | Витрина популярного | Чарты, новинки, метаданные, обложки, ISRC, рейтинг популярности, 30-секундные превью (API без ключа) |

Правила:
- С Jamendo импортируются только треки с `audiodownload_allowed = true`.
- Для каждого трека Jamendo хранится лицензия CC, автор и лицензия показываются в интерфейсе.
- Превью Deezer проигрываются напрямую с CDN Deezer и **на свой сервер не копируются**. Для ML они обрабатываются временно, хранятся только векторы-эмбеддинги.
- Полные популярные треки (Deezer / YouTube / Spotify и т. п.) не скачиваются: это нарушение авторских прав и правил платформ.
- Архитектура источников построена на адаптерах, поэтому позже можно подключить, например, Free Music Archive.

В интерфейсе два раздела:
- **«Популярное»:** чарты и новинки Deezer, превью;
- **«Полные треки»:** каталог Jamendo со своего сервера.

Рекомендации работают по обоим разделам, потому что эмбеддинги считаются для всех треков.

## 5. Архитектура и стек ✅ (по мотивам Spotify)

### 5.1. Соответствие стеку Spotify

| Spotify | Проект |
|---|---|
| Java, микросервисы (Spring, свой фреймворк Apollo) | Java 21 + Spring Boot 3, несколько сервисов |
| Kafka для событий | Apache Kafka (события прослушиваний, импорт треков) |
| React + TypeScript (веб и десктоп, общий код) | React + TypeScript |
| Десктоп: веб-интерфейс внутри Chromium (CEF) | Electron (тоже Chromium + веб-интерфейс) |
| Python для данных и ML | Python + PyTorch + FastAPI |
| Kubernetes, Docker, Google Cloud | Docker Compose (опционально k3s/minikube) |
| Нативные мобильные приложения | Не делаются, вместо них PWA |

### 5.2. Схема

```
            ┌─────────── React + TypeScript (один код) ───────────┐
            │                                                     │
  Веб (Nginx) → браузер ПК / телефон (PWA)       Electron → десктоп-приложение
            │                                                     │
            └────────── REST API + WebSocket (STOMP) ─────────────┘
                                   │
                         Nginx (API-шлюз, HLS)
                                   │
      ┌────────────────────────────┼────────────────────────────┐
      │                            │                            │
  core-api                   ingest-worker                  ml-service
  (Spring Boot)              (Spring Boot)                  (Python, FastAPI)
  пользователи, каталог,     импорт Jamendo,                эмбеддинги,
  плейлисты, комнаты, чат    ffmpeg → HLS                   рекомендации
      │                            │                            │
      └──────────────── Apache Kafka (события) ─────────────────┘
                                   │
            PostgreSQL + pgvector · Redis · MinIO (аудио, HLS)
```

### 5.3. Стек

| Слой | Технологии |
|---|---|
| **Бэкенд** | Java 21, Spring Boot 3, Gradle |
| Веб / API | Spring Web (REST), springdoc-openapi (Swagger) |
| Realtime | Spring WebSocket + STOMP (комнаты, синхронизация, чат) |
| Безопасность | Spring Security + JWT |
| Доступ к БД | Spring Data JPA (Hibernate), миграции Flyway |
| **Брокер событий** | Apache Kafka (режим KRaft) |
| **БД** | PostgreSQL + pgvector |
| Кэш / состояние | Redis: состояние комнат, онлайн-статусы, кэш внешних API |
| Хранилище аудио | MinIO (S3-совместимое) |
| Обработка аудио | ffmpeg → HLS (например, 64 / 128 / 256 кбит/с) |
| **Фронтенд** | React + TypeScript + Vite |
| Состояние / запросы | Redux Toolkit + RTK Query |
| Плеер | hls.js, Media Session API |
| Связь с бэкендом | TS-клиент, сгенерированный из OpenAPI; @stomp/stompjs |
| UI | Адаптивная вёрстка, PWA |
| **Десктоп** | Electron (тот же React-код) |
| **ML** | Python, PyTorch (CUDA 12.8+), FastAPI, Hugging Face Transformers (MERT / CLAP) |
| **Инфраструктура** | Docker Compose, Nginx |
| Мониторинг | Prometheus + Grafana (Spring Boot Actuator) |
| Тесты | JUnit 5, Testcontainers; Vitest / Playwright для фронта |

### 5.4. Сервисы

| Сервис | Ответственность |
|---|---|
| **core-api** | Авторизация, пользователи, каталог, поиск, плейлисты, лайки, комнаты совместного прослушивания, чат |
| **ingest-worker** | Импорт треков из Jamendo, загрузка метаданных Deezer, транскодинг в HLS |
| **ml-service** | Расчёт эмбеддингов, обучение моделей, выдача рекомендаций |

Взаимодействие через Kafka, топики:
- `track.imported`: трек загружен → ml-service считает эмбеддинг;
- `listening.events`: прослушивания, лайки, пропуски → данные для обучения;
- `recommendations.updated`: обновлены рекомендации пользователя.

### 5.5. Конвейер треков Jamendo
1. ingest-worker по расписанию забирает новые и популярные треки через API.
2. Оригиналы сохраняются в MinIO.
3. ffmpeg транскодирует их в HLS с несколькими битрейтами.
4. В Kafka публикуется событие `track.imported`.
5. ml-service считает аудио-эмбеддинг и записывает его в pgvector.
6. Nginx раздаёт HLS-сегменты клиентам.

## 6. Кроссплатформенность

### 6.1. Веб-версия (ПК и телефон)
- Адаптивный интерфейс: на телефоне нижняя навигация и полноэкранный плеер, на ПК боковая панель и плеер внизу.
- PWA: установка на главный экран телефона.
- Управление с экрана блокировки и из шторки (Media Session API).

### 6.2. Десктопное приложение (Electron)
Функции, которых нет в браузере:
- медиаклавиши и глобальные горячие клавиши;
- сворачивание в трей с продолжением воспроизведения;
- системные уведомления (сообщения, приглашения в комнату);
- офлайн-кэш треков (только Jamendo, где скачивание разрешено);
- мини-плеер поверх окон;
- автообновление (electron-updater).

Код общий, десктопные функции включаются проверкой «запущено в Electron».

## 7. Вычислительные ресурсы

| Устройство | Задачи |
|---|---|
| Ноутбук (без видеокарты) | Разработка, Docker-окружение, инференс эмбеддингов на CPU |
| Стационарный ПК: **Windows 11, NVIDIA RTX 5060 8 ГБ** | Массовый расчёт эмбеддингов, обучение моделей, сборка десктоп-версии для Windows. ML-воркер в Docker подключается к Kafka по сети |
| Запасной вариант | Google Colab / Kaggle (бесплатный GPU) |

### 7.1. Настройка ПК под ML
- Docker Desktop на бэкенде WSL2 + драйвер NVIDIA с поддержкой GPU в WSL2, чтобы контейнер ml-service видел видеокарту.
- RTX 5060 относится к поколению Blackwell, поэтому PyTorch нужен в сборке с CUDA 12.8 или новее (старые сборки эту карту не поддерживают).

### 7.2. Модели под 8 ГБ видеопамяти
| Задача | Модель | Комментарий |
|---|---|---|
| Аудио-эмбеддинги (основная) | **MERT-v1-95M** | Модель, обученная именно на музыке; ~95 млн параметров, свободно помещается в 8 ГБ |
| Аудио-эмбеддинги (альтернатива / бонус) | **CLAP** (LAION) | Общее пространство «текст ↔ аудио»: можно сделать поиск по описанию («спокойная музыка для учёбы») |
| Коллаборативная модель | Two-tower (PyTorch) / ALS | Небольшие модели, обучение на 8 ГБ без проблем |

### 7.3. Десктоп-сборка
- Целевая платформа: Windows 11, установщик .exe (NSIS) через electron-builder.

## 8. План разработки

1. **Каркас:** структура репозитория, Docker Compose (Postgres, Redis, Kafka, MinIO, Nginx), Spring Boot + Spring Security + JWT, базовый React UI.
2. **Каталог и плеер:** ingest-worker (Jamendo, ffmpeg → HLS), витрина Deezer, плеер, поиск, плейлисты.
3. **Совместное прослушивание:** WebSocket/STOMP, комнаты, синхронизация часов, команды хозяина, коррекция дрейфа.
4. **Мессенджер:** чат комнаты, личные сообщения, отправка треков.
5. **Сбор данных:** события прослушиваний в Kafka → хранилище для обучения.
6. **ML:** эмбеддинги → контентные рекомендации → коллаборативная модель → гибрид → сравнение метрик.
7. **Десктоп и PWA:** сборка Electron, десктопные функции, установка PWA.
8. **Оформление:** тестирование, мониторинг, замеры точности синхронизации (расхождение в мс), пояснительная записка.

## 9. Уровень подготовки

- Все технологии стека знакомы, кроме MinIO. Его нужно освоить, но порог входа низкий: MinIO совместим с API Amazon S3, работа с ним идёт через стандартный S3-клиент (AWS SDK for Java).
